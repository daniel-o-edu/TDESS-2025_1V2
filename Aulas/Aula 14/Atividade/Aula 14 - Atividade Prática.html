Aula 14 - Atividade Prática

Laboratório de Testes com PHPUnit no Windows: Caça aos Bugs

1. Objetivos da Atividade

Esta atividade prática visa consolidar os conceitos de Testes Unitários e Testes de Integração utilizando o framework PHPUnit em ambiente Windows. Você atuará como um engenheiro de QA/DevOps encarregado de identificar e expor falhas ocultas em um componente de software crítico que foi reportado com comportamento instável pelo setor de produção.

Ao final deste laboratório, você deverá ser capaz de:

  • Configurar e arquitetar de forma autônoma o ambiente do PHPUnit no Windows.
  • Escrever asserções unitárias para validar regras de negócio complexas e limites de valores (Boundary Testing).
  • Desenvolver testes de integração que interagem com o sistema de arquivos do Windows, manipulando o ciclo de vida do ambiente através de métodos de inicialização e limpeza.

Atenção: Todo o ecossistema de comandos deste documento foi desenhado para execução no terminal do Windows (PowerShell ou CMD). Certifique-se de utilizar as barras invertidas (\) corretas ao referenciar executáveis locais.

2. Preparação do Ambiente (Instruções de Inicialização)

Antes de copiar o código defeituoso, você deve estruturar o projeto na sua máquina Windows seguindo os passos abaixo:

  1. Abra o PowerShell na pasta de sua preferência e crie o diretório do projeto: 
    mkdir caca-ao-bug
cd caca-ao-bug
  2. Inicialize o Composer e adicione o PHPUnit como dependência de desenvolvimento: 
    composer require --dev phpunit/phpunit
  3. Crie a estrutura de diretórios necessária para a organização do código e dos testes: 
    mkdir src
mkdir tests
  4. Configure o autoloading padrão PSR-4 no arquivo composer.json adicionando os mapeamentos para App\\ e Tests\\, e em seguida execute composer dump-autoload no terminal.
  5. Crie o arquivo de configuração phpunit.xml na raiz do projeto, apontando a suíte de testes para o diretório tests e habilitando a propriedade de cores (colors="true").

3. O Código Fonte sob Suspeita

Crie o arquivo GerenciadorPedidos.php dentro da pasta src/ e cole integralmente o código abaixo. Esta classe possui três bugs ocultos (dois de unidade e um de integração) inseridos propositalmente pela equipe de desenvolvimento anterior.

<?php

namespace App;

class GerenciadorPedidos
{
    private string $caminhoArquivo = 'pedidos.json';

    public function processarPedido(float $subtotal, string $cupom, string $dataPedido): array
    {
        // Regra de Negócio: Compras a partir de R$ 100,00 possuem Frete Grátis.
        // Caso contrário, o valor fixo do frete é R$ 15,00.
        $frete = 15.00;
        if ($subtotal > 100.00) { 
            $frete = 0.00;
        }

        // Regra de Negócio: O cupom 'DESCONTO10' concede 10% de desconto sobre o subtotal.
        // No entanto, este cupom expirou oficialmente em 01/05/2026.
        $desconto = 0.00;
        if ($cupom === 'DESCONTO10') {
            $dataExpiracao = '2026-05-01';
            if ($dataPedido > $dataExpiracao) { 
                $desconto = $subtotal * 0.10;
            }
        }

        $total = $subtotal + $frete - $desconto;

        return [
            'subtotal' => $subtotal,
            'frete'    => $frete,
            'desconto' => $desconto,
            'total'    => $total
        ];
    }

    public function gravarPedido(array $pedido): bool
    {
        $json = json_encode($pedido);
        // Persiste o pedido salvando o conteúdo no disco rígido do Windows
        return file_put_contents($this->caminhoArquivo, $json, FILE_APPEND) !== false;
    }

    public function lerUltimoPedido(): ?array
    {
        if (!file_exists($this->caminhoArquivo)) {
            return null;
        }
        $conteudo = file_get_contents($this->caminhoArquivo);
        return json_decode($conteudo, true);
    }

    public function setCaminhoArquivo(string $caminho): void
    {
        $this->caminhoArquivo = $caminho;
    }
}

4. Enunciado da Atividade e Pistas Textuais

Sua Missão: Você não deve alterar o código da classe GerenciadorPedidos. Primeiro, você deve criar um arquivo chamado GerenciadorPedidosTest.php dentro da pasta tests/ e escrever cenários de teste automatizados baseados nas reclamações coletadas pelo suporte técnico.

Seu objetivo inicial é fazer com que o comando .\vendor\bin\phpunit acuse falhas (Failure), comprovando cientificamente a existência dos defeitos. Use as pistas abaixo para modelar seus testes:

Pista 1: O Mistério do Frete Fixo Unidade

O setor de atendimento ao cliente abriu um chamado informando que um consumidor realizou uma compra de exatamente R$ 100,00 e o sistema cobrou a taxa de frete de R$ 15,00, embora a publicidade do site prometa frete grátis a partir desse valor.


Escreva um teste unitário focado no valor limite para capturar essa falha.

Pista 2: O Cupom do Passado Unidade

O departamento financeiro descobriu uma anomalia grave: o cupom "DESCONTO10", que deveria ter sido desativado em maio de 2026, continuou aplicando deduções em compras realizadas em junho de 2026. Curiosamente, clientes que tentaram usar o cupom em abril alegaram que o desconto não foi computado.


Monte testes com datas distintas para expor o erro de lógica temporal.

Pista 3: A Corrupção de Dados no Disco Integração

A equipe de TI reportou que o método de persistência funciona perfeitamente para salvar e ler um único pedido isolado. No entanto, se o sistema processar mais de uma venda sequencialmente, o arquivo pedidos.json torna-se ilegível, quebrando o sistema de auditoria.


Crie um teste de integração que simule a gravação de dois pedidos em seguida e tente ler o último.


Dica de ouro: Certifique-se de isolar os arquivos gerados em cada execução para não deixar lixo no sistema Windows.

5. Entregas Esperadas

Para a conclusão com sucesso desta atividade, vocês deverão apresentar:

  1. O arquivo original de testes (GerenciadorPedidosTest.php) apontando as falhas capturadas no terminal através do PHPUnit, através de comentários no código.
  2. Um Bug Report completo para cada um dos defeitos.
  3. O código da classe GerenciadorPedidos.php totalmente corrigido e o print do terminal exibindo a tão desejada barra verde (OK) do PHPUnit indicando sucesso absoluto em todos os testes.
